# حِصّة

منصة بتجمع أساتذة التوجيهي في الأردن مع طلابهم. كل أستاذ إله صفحة فيها موادّه، والطالب بيشترك بكود تفعيل من الأستاذ.

الموجود حاليًا (المراحل 0 و1 و2 من خطة البناء):

- صفحات عامة، دخول برقم الموبايل، وموافقة ولي الأمر للطلاب تحت 18.
- لوحة الطالب: موادّه، تقدّمه، تفعيل الاشتراك بكود، واختبارات بتتصحّح تلقائيًا.
- لوحة الأستاذ: أكواد التفعيل، رفع ملفات PDF وفيديوهات، محرّر أسئلة الاختبارات، وقائمة طلابه وتقدّمهم.
- تقييمات حقيقية من الطلاب المشتركين بس.
- فيديو محمي عن طريق Bunny Stream.

## التشغيل على جهازك

```bash
npm install
npm run dev
```

افتح http://localhost:3000. بدون مفاتيح Supabase التطبيق بيشتغل **بنسخة تجريبية** ببيانات نموذجية:

- أي رقم أردني (مثلا 791234567) وكود الدخول `482913`.
- دخول الأساتذة بيفتح لوحة أ. خالد العمري.
- كود تفعيل للتجربة: `HS-KHALED-02`.
- اختبار جاهز للتجربة: "اختبار قصير: قواعد الاشتقاق" عند أ. خالد.
- التعديلات بالنسخة التجريبية بتنحفظ بالذاكرة وبتروح لما يرجع السيرفر يشتغل.

## ربط Supabase (التشغيل الحقيقي)

1. اعمل مشروع على https://supabase.com (الخطة المجانية بتكفي للبداية).
2. من **SQL Editor** شغّل ملفات `supabase/migrations/` بالترتيب (`0001` وبعده `0002`)، وبعدها `supabase/seed.sql` إذا بدك البيانات النموذجية.
3. من **Authentication → Providers** فعّل **Phone**، واربطه بمزوّد رسائل (Twilio أو MessageBird أو Vonage).
4. انسخ `.env.example` لـ `.env.local` وعبّي القيم من **Project Settings → API**.
5. `npm run build && npm start`.

### الفيديو (Bunny Stream)

1. اعمل حساب على https://bunny.net، وافتح **Stream** واعمل Video Library.
2. من إعدادات المكتبة خذ **Library ID** و **API Key**، وحطهم بـ `BUNNY_LIBRARY_ID` و `BUNNY_STREAM_API_KEY`.
3. من **Security** فعّل **Embed view token authentication**، وانسخ **Token authentication key** لـ `BUNNY_TOKEN_KEY`.
4. يفضّل كمان تحدد **Allowed referrers** لدومين المنصة.

الأستاذ بيرفع الفيديو من المتصفح مباشرة لـ Bunny (السيرفر بيوقّع الرفع بس)، والطالب بيشوفه برابط بينتهي بعد 3 ساعات وعليه علامة مائية باسمه. بدون هالمفاتيح، رفع الفيديو بيكون مسكّر وباقي المنصة بتشتغل عادي.

### ربط حساب أستاذ بصفحته

الأستاذ بيسجّل دخول برقمه مرة وحدة، وبعدها من SQL Editor:

```sql
update public.profiles set role = 'teacher', consent = 'not_needed' where phone = '962791234567';
update public.teachers set user_id = (select id from public.profiles where phone = '962791234567'), verified = true
where slug = 'khaled-omari';
```

## البنية

| المسار | شو فيه |
| --- | --- |
| `app/` | الصفحات (Next.js App Router) و `app/actions/` للعمليات على السيرفر |
| `lib/data.ts` | كل قراءة بيانات، بتشتغل على Supabase أو على البيانات النموذجية |
| `lib/session.ts` | مين داخل، وتحويل اللي مش داخل لصفحة الدخول |
| `supabase/` | الجداول وسياسات الحماية (RLS) والبيانات النموذجية |
| `prototype/` | النموذج التفاعلي الأصلي، مرجع للتصميم |
| `docs/` | التحليل وقائمة الإضافات |

## الحماية

- كل جدول عليه Row Level Security: الطالب بيشوف اشتراكاته بس، والأستاذ بيشوف طلابه وموادّه بس.
- الطالب ما بيقدر يغيّر دوره أو موافقته، والأستاذ ما بيقدر يوثّق حاله (trigger `protect_fields`).
- ملفات الـ PDF بـ bucket خاص، والسيرفر بيعطي رابط بينتهي بعد 10 دقايق بعد ما يتأكد من الاشتراك.
- الطالب تحت 18 ما بتنفتحله المواد قبل موافقة ولي الأمر (قانون حماية البيانات الشخصية رقم 24 لسنة 2023).
- أجوبة الاختبارات ما بتوصل لجهاز الطالب: التصحيح بيصير بقاعدة البيانات (`submit_quiz`)، والجواب الصح بيظهر بس بعد التسليم.
- التقييم للمشترك بس، مرة وحدة لكل أستاذ، والاسم بينحط من حسابه مش من الطلب. متوسط التقييم بيتحدّث لحاله.
